title: Testing tools
description: Checkers and assistive technology used with this library. Automated tools are not a conformance claim.

Official product pages stay the install and help source. These tools do not add WCAG requirements.

Checkers help you look at a page. They do not finish a WCAG-EM audit or a Trusted Tester pass. On this site’s isolated examples, close **Edit** before you scan so the editor is not in the page.

## In this section

| Tool | Job | Install |
| --- | --- | --- |
| [DevTools Accessibility](devtools/) | Heading tree, name, role, value — already in Chrome / Chromium | None |
| [axe DevTools](axe/) | Automated WCAG rules in a DevTools panel | [Install](axe/#install) |
| [WAVE](wave/) | Visual overlay of issues on the rendered page | Browser extension |
| [ANDI](andi/) | SSA inspector used in Trusted Tester v5 | Bookmarklet |
| [Screen reader](screen-reader/) | The heading list and names as a person hears them | OS / AT |

Process (how to plan an audit) stays on [WCAG-EM](../wcag-em/). Trusted Tester courses: [DHS Section 508 Training](../../definitions/dhs-508-training/).

## Try it on this site

Rules with isolated examples, such as [Do not skip heading levels](/learn/heading-order/), open a live bad or good page you can run a tool on. All leaves: [knowledge tree](/learn/).

## What none of these replace

Keyboard testing, a real screen reader, and a human judgement of “is this the same task.” See [WCAG-EM](../wcag-em/) and [Involving Users](https://www.w3.org/WAI/test-evaluate/involving-users/).
